# 地価ベースの水準ランク

営業リスト向けに、店舗の立地の「地価の水準」を5段階のランクとして付与する仕組みです。

実装は [`scripts/enrich/land-price-rank.js`](../scripts/enrich/land-price-rank.js)、テストは
`scripts/enrich/land-price-rank.test.js` にあります。

## これは賃料ではありません

**賃料の金額は公的オープンデータに存在しません。**

国土交通省の不動産情報ライブラリが公開しているのは、次の3種類です。賃料は含まれません。

| API | 内容 |
| --- | --- |
| XIT001 / XPT001 | 不動産価格（取引価格・成約価格） |
| XPT002 | 地価公示・地価調査のポイント |
| XCT001 | 鑑定評価書 |

したがって、ここで作れるのは**地価ベースの「水準ランク」**であって、実賃料ではありません。

**金額には換算しません。** 収益還元で出るのは土地の期待収益であって、テナント1区画の坪賃料ではないためです。
換算した時点で、根拠のない金額が営業資料に載ることになります。

出力する列も「ランク」と、その根拠になった「地価」「最寄り点までの距離」に留めています。

## API 利用申請

不動産情報ライブラリの API は無料ですが、**利用申請と承認が必要**です。

1. [API 利用申請画面](https://www.reinfolib.mlit.go.jp/api/request/) から必要事項を入力して申請する
2. 審査・承認の後、サブスクリプションキーが発行される

**審査は5営業日が目安です。** キーが無いと1件もデータを取得できないため、
この工程がリードタイムになります。実装より先に申請を出してください。

API の仕様は[操作説明（XPT002）](https://www.reinfolib.mlit.go.jp/help/apiManual/xpt002/)を参照してください。

## API キーの設定

キーは**環境変数から読みます。コードにもリポジトリにも書かないでください。**

| 項目 | 値 |
| --- | --- |
| 環境変数名 | `REINFOLIB_API_KEY` |
| リクエストヘッダ名 | `Ocp-Apim-Subscription-Key` |

```bash
export REINFOLIB_API_KEY='（発行されたサブスクリプションキー）'
npm run enrich:land-price -- --in=api/facilities-all.csv --out=facilities-with-rank.csv
```

環境変数が未設定のときは、**理由を表示して何もせずスキップ**します（異常終了はしません）。
黙って進んで空の列を作ることはありません。

> **未決:** 本番でキーをどこに置くか（AWS Secrets Manager 等）は決まっていません。
> 現状は環境変数から読む形にしてあるので、置き場所が決まれば呼び出し側で注入できます。

## 使い方

```bash
# 全国共通のランク（既定）
npm run enrich:land-price -- --in=<入力CSV> --out=<出力CSV>

# 都道府県内の相対ランクに切り替える
npm run enrich:land-price -- --in=<入力CSV> --out=<出力CSV> --rank-scope=prefecture

# 対象年を明示する（既定は後述のルールで自動決定）
npm run enrich:land-price -- --in=<入力CSV> --out=<出力CSV> --year=2026

# キャッシュを無視して取り直す
npm run enrich:land-price -- --in=<入力CSV> --out=<出力CSV> --force
```

入力 CSV は `lat` / `lng` 列を持つものを想定しています（配信している結合CSV・都道府県別CSV がそのまま使えます）。
出力は入力の全列に、次の3列を末尾へ足したものです。

## 出力する列

| 列 | 内容 |
| --- | --- |
| `land_price` | 最寄りの商業地ポイントの地価（円/㎡） |
| `land_price_distance_m` | その点までの距離（メートル、測地線距離） |
| `land_price_rank` | 5段階の水準ランク（1 = もっとも安い / 5 = もっとも高い） |

**距離の列を必ず一緒に見てください。** 地価のポイントは市街地には密にありますが、
郊外では数km離れていることがあります。距離が大きい行の `land_price` は参考値です。

## 仕組み

1. XPT002 はタイル単位（`z`/`x`/`y`、`z` は 13〜15）で点を返します。各店舗の座標が乗る
   z=13 のタイルと、その周囲8枚（3×3）を列挙します。
2. タイルごとに商業地（`useCategoryCode=05`）の点を取得し、`.cache/land-price/<年>/` に保存します。
   2回目以降はキャッシュを使い、API を叩き直しません（`--force` で無視できます）。
3. 取得した点をタイルで索引し、店舗ごとに3×3の近傍だけを走査して最寄り点を選びます。
   店舗×全ポイントの総当たりはしません。

周囲8枚も取得するのは、最寄りの商業地ポイントが隣のタイルにあることが普通にあるためです。
3×3なら、店舗がタイルの隅にあってもどの方角にも最低1タイル分（日本の緯度帯で3.4km以上）を走査できます。

### 対象年

地価公示は毎年3月下旬に公表されます（価格時点は当年1月1日）。まだ公表前の1〜3月に当年を
指定すると空振りするため、既定では**4月以降なら当年、1〜3月なら前年**を使います。
`--year` で明示的に上書きできます。

### ランクの切り方

全国共通の固定金額ではなく、**取得した商業地ポイントの分位**（20/40/60/80 パーセンタイル）で切ります。
地価は毎年変わるうえ、都市と郡部で桁が違うため、円の絶対値を定数で持つと数年で意味を失うからです。

母集団の取り方は2通りあり、`--rank-scope` で切り替えられます。

| scope | 母集団 | 読み方 |
| --- | --- | --- |
| `national`（既定） | 全国の商業地ポイント | 全国で横に並べたときの水準。郡部はほぼ 1 に寄る |
| `prefecture` | 都道府県ごと | その県の中で高いか。県をまたいだ比較はできなくなる |

`prefecture` を指定しても、点が少なすぎる県（25点未満）は全国の閾値にフォールバックします。
少ない母集団で分位を取ると、1点動いただけでランクが総入れ替えになるためです。

### ランクを付けない条件

最寄り点までの距離が **3,000m** を超えた場合、`land_price` と `land_price_distance_m` は残したまま、
`land_price_rank` だけを空にします。理由は2つあります。

1. **意味の問題。** 数km離れた地価公示ポイントは、その店舗の立地の水準を表しません。
   遠くの点をそのまま5段階に押し込むと、根拠のないランクが出ます。
2. **探索範囲の問題。** 3×3の近傍で保証できるのは最低3.4km程度です。それを超える距離で
   見つかった点は「たまたま近傍タイルに入っていただけ」で、真の最寄り点である保証がありません。

近傍に点が1つも無い店舗と、座標を持たない店舗は、3列とも空になります。

## 採らなかった選択肢

### 国税庁の路線価

道路単位で密にあり、賃料との相関も高いと期待できます。ただし公開形式が PDF / 画像中心で、
**整形コストが大きい**ためすぐには採りません。

**まず地価ベースのランクが営業の役に立つと確認してから**、路線価に投資するかを判断します。

### 民間の実賃料データ

- 各社サイトのスクレイピングは**規約違反**です。
- 国立情報学研究所の LIFULL HOME'S データセットは**学術研究用途に限定**されており、営業利用はできません。

## 未決の論点

いずれも決まっていません。推測で埋めずに、決めたらこのファイルを更新してください。

- **ランクで足りるか、金額が要るか。** 金額が要るなら公的データでは作れないため、方針から見直しになります。
- **ランクの切り方。** 全国共通（既定）と都道府県内の相対のどちらを本番にするか。
- **API キーの管理場所。** Secrets Manager 等に置くか。
- **路線価に投資するか。** ランクが営業の役に立つと確認できてから判断します。
