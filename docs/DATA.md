# データの詳細

Japan Food Facilitiesで配信しているデータの収集元、加工方法、収録範囲、位置情報の精度について説明します。

## 1レコードの単位

1レコードは、原則として1件の営業許可または届出を表します。

同じ施設が複数の業種で許可を持つ場合は、業種ごとに複数レコードとして収録されます。

そのため、レコード数と実際の施設数は一致しません。

## データの収集元

データは主に次の順序で収集しています。

1. 市区町村が公開するオープンデータ
2. 都道府県や保健所設置主体が公開するオープンデータ
3. 厚生労働省「食品衛生申請等システム（i2fas）」のオープンデータ

複数の公開元で同じ地域のデータが提供されている場合は、原則として、より地域に近い自治体が公開するデータを優先します。

自治体ごとの収録状況と取得元は、[`COVERAGE.md`](COVERAGE.md)で確認できます。

## 市区町村名の正規化

市区町村名は、[normalize-japanese-addresses](https://github.com/geolonia/normalize-japanese-addresses)を利用して正規化しています。

データの粒度を市区町村単位に統一するため、次の加工を行っています。

* 政令指定都市の行政区は市に集約
  例：`横浜市戸塚区` → `横浜市`
* 町村は郡名を除去
  例：`河北郡津幡町` → `津幡町`
* 元データの市区町村表記は`city_raw`列に保存

正規化後の市区町村名は`city`列に格納されます。

都道府県や市区町村を特定できなかった場合は、該当する列に`不明`が入ります。

## 収録範囲

全国1,741市区町村のうち、**1,727市区町村（99%）**のデータを収録しています。

ただし、自治体のデータを収録していても、その自治体内に存在するすべての施設が含まれているとは限りません。

公開元によって、収録期間、更新頻度、対象業種、公開対象となる施設の条件が異なります。

自治体ごとの詳しい収録状況は、[`COVERAGE.md`](COVERAGE.md)を参照してください。

## 緯度経度

元データに緯度経度が含まれていない場合は、住所をもとにジオコーディングしています。

ジオコーディングにも、市区町村名の正規化と同じ[normalize-japanese-addresses](https://github.com/geolonia/normalize-japanese-addresses)を利用しています。

緯度経度はWGS84形式で、`lat`列と`lng`列に格納されます。

ジオコーディング結果のおおよその精度は、`geocoding_level`列で確認できます。この値はnormalize-japanese-addressesが返す正規化レベルです。

| level | 精度       |
| ----- | -------- |
| `1`   | 都道府県の代表点 |
| `2`   | 市区町村の代表点 |
| `3`   | 町丁目の代表点  |
| `8`   | 街区・地番レベル |

値が小さいほど、位置は大まかです。列が空欄の場合は、元データに含まれていた緯度経度をそのまま使っていることを表します。

建物単位の位置精度が必要な場合は、必ず`geocoding_level`を確認してください。

「市内一円」など、住所から正確な位置を特定できないデータには、緯度経度を付与していない場合があります。

### 座標の品質フィルタ

図解つきの解説は[座標の品質](https://gl20percentclub.github.io/japan-food-facilities/coord-quality.html)にあります。

施設の位置として信用できない緯度経度は、配信前に取り除いています。取り除くのは緯度経度だけで、レコード自体は残ります。施設名・住所・業種・許可番号はそのまま利用できます。

| 取り除く座標                     | 理由                                                             |
| -------------------------- | -------------------------------------------------------------- |
| 「市内一円」など実体のない住所に付いていた座標    | 位置を特定できない施設が1点に積み上がるため。移動販売・キッチンカーに多い                          |
| `geocoding_level`が`1`または`2`| 都道府県・市区町村の代表点。`prefecture`列・`city`列で表せる情報しか持たず、地図上では庁舎の一点に集中する |
| 都道府県の行政界の外に落ちている座標         | 元データの座標が別の自治体のものと入れ替わっているもの。境界付近は約1kmの余裕を持たせて判定する               |

### 同一施設の座標の統一

同じ施設が複数の公開元に載っている場合や、業種違いの許可レコードとして複数行に分かれている場合、同じ施設に少しずつ違う緯度経度が付くことがあります。

施設名を正規化して一致し、かつ50m以内にある座標は、1点に統一しています。統一後の座標には、そのまとまりの中でもっとも精度の高いもの（元データの座標 → `level 8` → `level 3`の順、同順位なら中央値）を使います。

座標が動く距離は50m以下に収まります。統一後の座標から50mを超える行は、そのまとまりに含まれていても動かしません。

`geocoding_level`は統一後も書き換えません。その行の住所から解けた精度は変わらないため、この列は精度の下限を表します。

## 鮮度と網羅性

次のようなデータが含まれる場合があります。

* 古い時点のスナップショット
* 掲載に同意した施設だけを含むデータ
* 廃業後も公開元に残っている施設
* 許可期限が切れている施設
* 市区町村を特定できない施設
* 所在地を正確に特定できない施設
* 元データに緯度経度が含まれていない施設

本データは、各公開元のデータを収集・加工したものです。

最新かつ正式な情報が必要な場合は、各自治体やデータ提供元が公開する情報を確認してください。

## 更新頻度

毎週月曜18:00 UTC、日本時間の火曜3:00にデータを自動更新します。

更新後も、CSVおよびベクトルタイルのURLは変わりません。

公開元のURL、ファイル形式、配信方法が変更された場合などには、一時的に更新できないデータが発生することがあります。
